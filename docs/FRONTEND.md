# Интерфейс гостя

React 19 + TypeScript + Vite, каталог [`frontend/`](../frontend). Внешних UI-библиотек нет: разметка и стили повторяют согласованный макет, токены оформления собраны в `src/styles.css`. Маршрутизация — `react-router-dom`. Интерфейс обращается только к публичным endpoints из [API-контракта](API_CONTRACT.md) и не хранит ничего, кроме выданных токенов брони.

## Структура

| Путь | Назначение |
| --- | --- |
| `src/api/client.ts` | Единственная точка вызова API: заголовок `X-Booking-Access-Token`, разбор `{"detail": ...}`, `ApiError` со статусом и `NetworkError` |
| `src/api/types.ts` | Типы ответов, повторяющие `app/schemas.py` |
| `src/lib/format.ts` | Деньги, даты, число ночей, русские формы множественного числа |
| `src/lib/stay.ts` | Клиентская проверка периода и числа гостей, разбор и сборка query-параметров |
| `src/lib/storage.ts` | Список броней этого браузера в `localStorage` |
| `src/lib/images.ts` | Привязка встроенных SVG-иллюстраций к номеру |
| `src/lib/useAsync.ts` | Загрузка с отменой запроса и повторной попыткой |
| `src/components/` | Форма поиска, карточка номера, галерея, статусы, состояния загрузки и ошибок |
| `src/pages/` | Экраны: поиск, результаты, карточка номера, мои брони |

## Экраны

**Поиск (`/`).** Заголовок, иллюстрация корпуса, панель поиска с датами и числом гостей. Ниже — номера, свободные на текущие даты формы: это живой ответ `GET /api/rooms/search`, а не статичный список.

**Результаты (`/rooms?check_in=…&check_out=…&guests=…`).** Параметры периода живут в URL, поэтому ссылку на выдачу можно открыть повторно. Слева фильтры: максимальная цена за ночь и категории, собранные из полученных номеров. Фильтры сужают ответ сервера на клиенте; саму доступность проверяет только backend.

**Карточка номера (`/rooms/:roomId`).** Галерея с переключением, описание и удобства из `GET /api/rooms/{room_id}`. Панель брони пересчитывает `тариф × ночи` целыми тийын, проверяет вместимость номера и при смене дат заново запрашивает поиск, чтобы занятый период был виден до нажатия кнопки. После `POST /api/bookings` панель показывает номер брони и одноразовый токен и сохраняет их в браузере.

**Мои брони (`/bookings`).** Для каждой сохранённой брони выполняется `GET /api/bookings/{booking_id}` с токеном. Доступны демонстрационная оплата (`SUCCEEDED` и `FAILED`), отмена с подтверждением и обновление состояния. Отменённую или неизвестную серверу бронь можно убрать из локального списка; сама запись в базе при этом не меняется.

## Состояния

- **Загрузка.** Скелетоны для списков номеров, спиннер со `role="status"` для карточек и состояний брони.
- **Пустой результат.** `200 []` показывается как «свободных номеров нет» с переходом к изменению поиска; отдельный текст — когда номера есть, но их скрыли фильтры.
- **Ошибки.** `ApiError` показывает `detail` сервера, `422` — первое поле и сообщение, `409` — предложение повторить, `503` и `5xx` — отдельные тексты про базу и сервер. Недоступный backend (`NetworkError`) объясняет, что uvicorn не отвечает. Все блоки ошибок имеют `role="alert"` и кнопку повтора там, где повтор осмыслен.
- **Валидация.** Правила повторяют `Stay` из `app/schemas.py`: существующие календарные даты, выезд строго позже заезда, заезд не в прошлом, гостей от 1. Дополнительно интерфейс не даёт отправить число гостей больше вместимости номера — тот же случай backend возвращает как `400`.

## Хранение токена

API выдаёт `access_token` один раз и не умеет его восстанавливать, поэтому брони этого браузера лежат в `localStorage` под ключом `hotel.bookings.v1`. Записи содержат ID, токен и копию условий для показа списка; актуальное состояние всегда берётся у сервера. При заблокированном хранилище бронь всё равно создаётся, а токен остаётся на экране подтверждения.

## Доступность и адаптивность

Кнопки и поля не ниже 44 px, видимая обводка фокуса, подписи у всех полей, `aria-invalid` на полях с ошибкой, `aria-live` на изменяемых счётчиках и статусах. Раскладка перестраивается в одну колонку на ширине до 640 px: фильтры и панель брони перестают быть прилипающими, галерея уменьшается.
