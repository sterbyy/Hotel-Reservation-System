# Статическая проверка Python

Bandit сканирует Python-код в `app/` и `migrations/`. GitHub Actions запускает проверку при push, pull request и по ручному запуску. Workflow использует только право чтения репозитория. SAST-зависимость зафиксирована отдельно от зависимостей backend и pytest. [Workflow](../.github/workflows/sast.yml) · [Bandit](https://bandit.readthedocs.io/en/1.9.4/)

| Повторный, те же версии | 0 | 0 | 0 | Одно точечное исключение B105, ошибки разбора отсутствуют |

Замечание B105 проверено по коду. Константа `X-Booking-Access-Token` задаёт имя HTTP-заголовка. Значение токена генерируется при создании брони. Исключение `# nosec B105` подавляет только это правило на одной строке, остальные правила остаются активными. Скан проходил локально. Запуск на GitHub не проверялся.

## Повтор перед сдачей

Команды PowerShell из корня репозитория.

```powershell
py -3.13 -m venv .venv-sast
.\.venv-sast\Scripts\python.exe -m pip install -r requirements-sast.txt
.\.venv-sast\Scripts\python.exe -m bandit -r app migrations
```

Для проверки исключений выполните тот же скан с `--ignore-nosec`. В текущем коде он повторно покажет описанный B105 и завершится с кодом 1. Для сохранения машинного отчёта добавьте `-f json -o <путь-к-отчёту>`. Скан охватывает Python-код приложения и миграций. Проверка зависимостей, SQL-файлов и работающего API в этот запуск не входят.
